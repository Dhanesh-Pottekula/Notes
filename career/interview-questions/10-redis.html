Redis — beyond caching

366 questions · L1 84 · L2 194 · L3 88 · 20 sub-topics

Redis appears in nearly every design round as "put a cache here", but good interviewers keep going: why it is fast, how its data types are stored, what happens on failover, how Streams and consumer groups work, and whether a Redis lock is actually safe. You used Redis for locks, Streams and queues at AiRA, so expect deep follow-ups on those. Syllabus: 2B Redis (../../syllabus.html).

10.1 Why Redis is fast — the threading model

Learn: DDIA ch7 "Actual serial execution" (pdf p265–270) · Redis in Action (Josiah Carlson) ch.1 · redis.io/docs/latest/operate/oss_and_stack/management/optimization/latency/ · redis.io/docs/latest/develop/reference/protocol-spec/

  • L1 What is Redis, in one sentence?
  • L1 Why is Redis so fast?
    in memory, single-threaded execution, I/O multiplexing, compact data structures, simple protocol
  • L1 Is Redis single-threaded? Be precise.
    commands run on one thread; helper threads for I/O, freeing memory, fsync
  • L1 Rough latency and throughput of one Redis instance?
    sub-millisecond; around 100k+ simple ops/s per instance
  • L1 What is RESP?
    the Redis wire protocol; RESP3 arrived in Redis 6
  • L2 What is I/O multiplexing (epoll / kqueue), and how does the Redis event loop use it?
  • L2 Why did Redis choose one thread for commands? What does that buy you?
    no locks, every command atomic, simple; CPU rarely the bottleneck
  • L2 What do io-threads in Redis 6+ do, and what do they not do?
    socket reads/writes and parsing; commands still run on one thread
  • L2 One command takes 2 seconds. What happens to every other client?
  • L2 Name commands that can block the event loop.
    KEYS, sync FLUSHALL, DEL of huge keys, HGETALL/SMEMBERS on huge keys, long Lua
  • L2 UNLINK vs DEL. What is lazy freeing?
    UNLINK reclaims memory in a background thread
  • L2 Redis uses 100% of one core on a 16-core box. What are your options?
    shard with Cluster, read replicas, io-threads, fix slow commands
  • L2 What runs in child processes or background threads?
    fork for RDB and AOF rewrite; threads for fsync and lazy free
  • L3 Why does fork() cause latency spikes on a big instance?
    copying page tables; transparent huge pages make copy-on-write worse
  • L3 How does one thread serve 10,000 client connections?
  • L3 Is Redis usually CPU-bound, memory-bound or network-bound? How would you show it?
  • L3 KeyDB and Dragonfly are multi-threaded. Why didn't Redis go fully multi-threaded?

10.5 TTL, expiry and eviction

Learn: DBI ch5 "Page Replacement" (pdf p151–156) · redis.io/docs/latest/develop/reference/eviction/ · redis.io/docs/latest/commands/expire/

  • L1 What does EXPIRE do? What do TTL results -1 and -2 mean?
    -1: no expiry; -2: key does not exist
  • L1 What is maxmemory?
  • L1 Name the eviction policies.
    noeviction; allkeys/volatile × lru/lfu/random; volatile-ttl
  • L2 How does Redis expire keys? Lazy vs active expiry.
    checked on access, plus a periodic random sample of keys with TTL
  • L2 A million keys get the same TTL. What happens when they expire together?
    expiry CPU spike and a stampede on the DB; add jitter
  • L2 Does SET on an existing key keep its TTL?
    no, it clears it unless you pass KEEPTTL
  • L2 Which of PERSIST, SET, INCR, RENAME clear or keep a TTL?
  • L2 allkeys-lru vs volatile-lru vs allkeys-lfu: which for a pure cache, and which when Redis also holds data that must stay?
    volatile-* evicts only keys with a TTL
  • L2 What happens under noeviction when memory is full?
    writes fail with an OOM error; reads still work
  • L2 Is Redis LRU exact? How does the approximation work?
    samples maxmemory-samples keys (default 5); keeps an eviction pool
  • L2 LRU vs LFU: when does LFU win?
    one-off scans no longer push out frequently used keys
  • L2 How does Redis count access frequency for LFU in so few bits?
    8-bit logarithmic counter that decays over time
  • L2 Do replicas expire keys on their own?
    no; the primary sends DEL when a key expires
  • L3 Memory is at maxmemory, evictions are zero and writes fail. Why?
    noeviction, or volatile-* policy with no keys carrying TTL
  • L3 Why might expired keys still hold memory, and how do you see it?
    active expiry falls behind; check expired_keys and INFO keyspace
  • L3 Why can RSS be much larger than used_memory?
    fragmentation, copy-on-write during fork, allocator overhead
  • L3 A cache and a durable job queue share one Redis instance. What goes wrong under memory pressure?
    eviction drops queue keys; use separate instances
