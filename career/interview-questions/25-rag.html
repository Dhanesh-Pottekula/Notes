RAG — retrieval-augmented generation

329 questions · L1 70 · L2 159 · L3 100 · 18 sub-topics

RAG is the most common LLM system you will be asked to design, build or debug. Interviewers want the whole pipeline — parsing, chunking, embedding, hybrid retrieval, reranking, context assembly, citations — plus how you measure it and what you do when "the answer is wrong". A 3-year AI engineer must reason about each stage's failure modes and trade-offs, and tell real stories (Perplexity Mini, AiRA memory). Vector-index internals live in file 13; LLM basics in file 24.   • L2 How do you chunk tables so a row stays understandable?

  • L2 How much overlap do you use, and what does overlap cost?

  • L2 Chunk by tokens or by characters? Why does it matter?
  • L2 What is contextual chunk headers / contextual retrieval?

  • L2 Web pages vs PDFs vs chat transcripts: would you use the same chunker for all three?
  • L3 Different questions need different granularity (a fact vs a summary). How do you serve both?
    multi-granularity index, parent-document, summaries per section
  • L3 What is late chunking, and how does it differ from chunk-then-embed?
  • L3 How would you run an experiment to pick chunk size and overlap?

  • L3 You re-chunk the corpus. What else must change (IDs, citations, caches, evals)?
