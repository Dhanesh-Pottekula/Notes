29.1 URL shortener (Bitly / TinyURL)

Learn: System Design Interview (Xu) vol1 ch8 · HelloInt breakdown "Bitly" (hellointerview.com/learn/system-design/problem-breakdowns/overview) · github.com/donnemartin/system-design-primer (Pastebin solution)

Opening

  • L1 Design a URL shortener like bit.ly.

Clarify

  • L2 What do you ask first?
    custom aliases, expiry, analytics, read:write ratio, scale, deletion
  • L2 Do short links ever change destination? Do the same long URLs get the same short code?

Estimate

  • L2 100M new URLs a month, 100:1 reads to writes. Estimate write QPS, read QPS and 5-year storage.
  • L2 How long must the short code be for 5 years of URLs in base62?
    62⁷ ≈ 3.5 trillion; 7 chars is plenty

Deep dives

  • L2 What APIs do you expose? What does the redirect response look like?
    POST /urls, GET /{code}; 301 vs 302
  • L2 301 vs 302 redirect: which do you pick and how does it affect analytics?
  • L2 How do you generate the short code? Hash vs counter vs random.
    hash+collision check, counter+base62, ID ranges per server
  • L2 Hashing the long URL and taking 7 chars: how do you handle collisions?
  • L2 A global counter is a bottleneck. How do you hand out ID ranges?
    ticket server / ZooKeeper allocates blocks per app server
  • L2 Which database do you use and what is the schema?
  • L2 How do you cache redirects? What hit ratio do you expect?
  • L2 How do you handle custom aliases and their uniqueness?
  • L2 How do you expire links and clean them up?
  • L3 Sequential codes are guessable. Why does that matter and how do you fix it?
    enumeration of private links; shuffle/encrypt the counter
  • L3 How do you count clicks per link without slowing the redirect?
    async event to queue, batch aggregate
  • L3 How do you stop the shortener being used for phishing and spam?
  • L3 One link goes viral at 500k redirects/s. What breaks and what saves you?
  • L3 How do you make this multi-region with low-latency redirects everywhere?

Clarify

  • L2 What do you clarify for the key-value store?
    value size, read/write ratio, consistency needs, latency, availability target, scale
  • L2 Strong or eventual consistency — and can the client choose per request?

Estimate

  • L2 10 TB of data, 3 replicas, 2 TB per node. How many nodes, and how many per partition?

  • L2 How do you replicate each key? Which nodes hold the replicas?

  • L2 How do you handle a node that is down for 10 minutes?

  • L3 Two clients write the same key concurrently on different replicas. How do you detect and resolve the conflict?

  • L3 How do replicas that missed writes catch up?

  • L3 How do you add a node and move data without downtime?
  • L3 How do you support TTLs and deletes? What are tombstones and why keep them?
  • L3 How do you handle a hot key that one partition cannot serve?
