How to prepare each section (the routine)

  1. Read the "Learn" source for the section (study page first).
  2. Close it. Explain each topic out loud or write 3 lines per topic from memory.
  3. Answer every question out loud, timed (2 min concept, 5 min "design/compare", 45 min full design).
  4. Tie at least one answer per section back to your own work (AiRA, Jigsaw, StreetDine) — that is what makes a 3-year answer sound senior.
  5. Tick the box. Re-test ticked boxes every Sunday (spaced repetition).

How questions are written (for humans and agents)

A topic's questions are indented bullets right under its line, one question per line, never wrapped:

- [ ] TTL, eviction policies (LRU/LFU, `allkeys-lru`), memory limits ↳ https://redis.io/docs/latest/develop/reference/eviction/
  - `L1` What does TTL do in Redis, and how do you set it?
  - `L2` `allkeys-lru` vs `volatile-lru`: when would you pick each? ↳ which keys may be evicted; no-TTL keys
  - `L3` Memory is full and writes fail with OOM: walk me through what you check ↳ maxmemory, policy, big keys
  1. Level tag first, as inline code: L1 fundamentals (definitions, "what is X", "difference between") · L2 the standard question for a 3-year engineer (how it works, trade-offs, when to use, debugging) · L3 deep / senior / follow-up-of-a-follow-up (internals, failure modes, design at scale). List L1, then L2, then L3.
  2. Optional hint after ↳ : at most 15 words naming what a good answer must contain. For tricky, trap or scenario questions only. Never a full answer.
  3. Put a question under the most specific topic a learner of that topic should be able to answer it from. If no topic fits, add a new topic line to the right section rather than parking it somewhere loose.
  4. Kinds worth covering per topic: definition · how it works inside · X vs Y · when not to use · trade-off · what breaks · debugging scenario · design / implement it · numbers and limits · "where did you use this at AiRA".
  5. Markdown allowed inside a question: inline code, bold, italics, [text](url). Plain interviewer words.
  6. Other sub-bullets (like **Notes:** links) stay visible on the page; only level-tagged ones become questions. Question ticks are keyed by the question's text, so editing a question resets only its own tick.
  7. Spoken answer (optional): one - **Answer:** … sub-bullet right under the topic line, on a single line, with ¶ between paragraphs. It is one continuous, first-person answer that covers every question of that topic, the way you'd say it in an interview, using only facts you can back up. It shows right under the topic line, always open.
