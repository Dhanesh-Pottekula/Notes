Django vs Flask vs FastAPI vs Starlette

What web frameworks are, how they talk to servers (WSGI and ASGI), how async runs, why FastAPI benchmarks fast, and how Starlette, FastAPI and Uvicorn fit together. Pairs with sections 27.13–27.17 of the question bank.

1. What is FastAPI?

  • A modern Python web framework for building APIs (REST APIs, microservices, AI backends).
  • Designed around asynchronous programming with async and await.
  • Uses Python type annotations for request validation.
  • Uses Pydantic for data validation and serialization.
  • Generates API documentation automatically using OpenAPI.
  • Built on top of Starlette.

Common use cases: AI/LLM applications, RAG pipelines, microservices, REST APIs and WebSocket applications.

3. What is ASGI?

ASGI = Asynchronous Server Gateway Interface. A standard interface that defines how an asynchronous Python application talks to an application server.

Its responsibilities:

  • Supporting asynchronous HTTP request handling.
  • Supporting WebSocket connections.
  • Managing application lifespan (startup and shutdown).
  • Enabling concurrent I/O operations.

ASGI servers: Uvicorn, Hypercorn, Daphne.

4. What is WSGI?

WSGI = Web Server Gateway Interface. The traditional standard interface between Python web servers and Python web applications.

  • Traditionally synchronous request handling.
  • Designed mainly for HTTP request–response applications.
  • No native WebSocket support.
  • Common with traditional Flask and Django deployments.

Important: ASGI does not automatically make an application asynchronous. The application and its dependencies must support asynchronous execution.

6. Does Django support ASGI?

Yes. Django supports both WSGI and ASGI.

  • ASGI support arrived in Django 3.0.
  • Django supports asynchronous views and middleware.
  • Modern Django supports asynchronous ORM operations.
  • Django can run on Uvicorn or Daphne.

A Django project generally contains:

myproject/
    settings.py
    urls.py
    asgi.py
    wsgi.py

Run it with ASGI:

uvicorn myproject.asgi:application

Remember: Django is not limited to WSGI. It supports both interfaces.

7. What is Starlette?

Definition: Starlette is a lightweight Python ASGI framework/toolkit that provides the underlying web infrastructure FastAPI uses.

It handles the basic web operations:

  • Routing – maps URLs to endpoint functions.
  • Middleware – processes incoming requests and outgoing responses.
  • Request/Response – handles HTTP communication.
  • WebSockets – real-time, two-way communication.
  • Lifespan – startup and shutdown events.
  • ASGI integration – talks through the ASGI interface.

Starlette can also be used on its own, without FastAPI.

9. Why FastAPI usually beats Django in API benchmarks

Both support ASGI, so ASGI alone is not the reason. The factors:

  1. Lightweight architecture: less full-stack functionality to carry than Django.
  2. Starlette: efficient ASGI-based web infrastructure.
  3. API-focused design: built specifically for API development.
  4. Request validation: structured validation with Pydantic.
  5. Async-first: asynchronous programming feels natural.
  6. Less framework overhead: fewer framework operations for a simple API request.

Real performance still depends on the implementation, middleware, database drivers, serialization and workload.

Important: FastAPI is not always faster than Django. An optimized Django application can outperform a poorly written FastAPI application.

10. Async and await

Async programming helps most with I/O-bound work.

@app.get("/generate")
async def generate():
    response = await llm_client.generate("Hello")
    return {"response": response}

How it runs:

  1. The request arrives.
  2. Python starts the LLM API call.
  3. Execution reaches await.
  4. The coroutine suspends while it waits for the network response.
  5. The event loop runs other ready tasks meanwhile.
  6. When the LLM answers, execution resumes.
  7. The API returns the result.
TermMeaning
asyncDefines a coroutine function
awaitSuspends the current coroutine until the awaited operation finishes
Event loopSchedules and runs asynchronous tasks
ConcurrencyMany tasks make progress in overlapping time periods
I/O-boundWork that mostly waits on external resources (network, disk, DB)
CPU-boundWork that needs a lot of computation

Async does not make CPU-heavy work faster. Django under ASGI can use the same async I/O pattern with async views and async-compatible libraries.

11. Automatic validation in FastAPI

FastAPI uses Python type annotations and Pydantic.

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class User(BaseModel):
    name: str
    age: int
    email: str

@app.post("/users")
def create_user(user: User):
    return user

Benefits:

  • Validates incoming JSON.
  • Checks data types.
  • Finds missing required fields.
  • Returns structured validation errors (HTTP 422).
  • Generates API schemas automatically.

The distinction to remember:

  • WSGI and ASGI are communication interfaces.
  • Uvicorn is a server.
  • Starlette is a web framework.
  • FastAPI is built on Starlette.
  • Pydantic handles data validation.
  • Django is a full-stack framework that supports both WSGI and ASGI.
  • Flask is a lightweight framework with WSGI roots and support for async views.

15. Follow-ups interviewers push on (added)

Added to your notes: the next questions that usually follow these answers.

  • def vs async def in FastAPI. A plain def endpoint runs in a thread pool, so blocking code there is fine. An async def endpoint runs on the event loop: a blocking call inside it (time.sleep, requests.get, a sync DB driver) freezes every request on that worker. Use async libraries (httpx, asyncpg) or move the call off the loop with run_in_threadpool / asyncio.to_thread.
  • CPU-bound work (embeddings on CPU, PDF parsing, image work) blocks the loop no matter what. Send it to a process pool or a task queue (Celery/RQ/arq), or run more worker processes.
  • Production setup: several worker processes, one event loop each, e.g. uvicorn app:app --workers 4 or Gunicorn managing Uvicorn workers. Workers ≈ CPU cores; each worker handles many concurrent I/O-bound requests.
  • Flask async views (Flask 2.0+) still run on WSGI: each async view gets its own event loop inside the request's thread, so you can await several calls in parallel inside one request, but the server does not handle more requests at once because of it.
  • Django's async ORM (aget, acreate, async for, Django 4.1+) is an async interface; the queries themselves still run through a thread (sync_to_async). Mixing sync code into async views costs a thread hop each time.
  • Dependency injection in FastAPI: Depends() builds per-request things (DB session, current user) and a dependency with yield runs cleanup after the response — that's how sessions get closed.
  • Lifespan: open shared clients once (DB pool, Redis, HTTP client, model load) at startup and close them at shutdown, instead of creating one per request.
  • Streaming LLM output: StreamingResponse or Server-Sent Events from an async generator; WebSockets only when the client also needs to send messages mid-stream.
