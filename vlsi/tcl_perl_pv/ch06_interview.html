Part 6 · Interview practice · weeks 11–12

Scripting questions for PV interviews, with worked answers

The scripting round is usually small problems on a whiteboard or shared editor, plus "tell me about a script you wrote". Answer each question on paper first, then open the answer. Every answer that contains code was executed, so the output printed under it is what the code really does.

How the scripting round usually goes

  • Small language problems: reverse a list, count words, find duplicates, parse a line. They test whether you really write code or only edit other people's.
  • Read this code: "what does this print?" Quoting in Tcl and context in Perl are the favourite traps.
  • Your own work: "what did you automate?" Have one project you can explain: problem, approach, a bug, time saved.
  • Scenario: "you have 5,000 DRC errors, what do you do?" The strong answer always includes sorting, grouping and comparing with scripts.

Say your plan out loud before writing: input, data structure, loop, output. Interviewers score the thinking more than the syntax.

Tcl

1. What is the difference between "..." and {...}?

Both group words into one. Inside double quotes, variables and commands are still substituted. Inside braces nothing is substituted; the text is passed as it is, and the command receiving it may evaluate it later (this is what if, while, proc and expr do).

2. Reverse a list without lreverse.

Follow-up they may ask: "is it efficient?" Inserting at the front copies the list each time. Walking the index down from [llength $l]-1 and using lappend is better for long lists.

3. Remove duplicates from a list but keep the original order.

lsort -unique removes duplicates but sorts. To keep order, remember what you have seen.

4. Count how many times each word appears in a file.
5. What does this print, and why? set a 5; set b a; puts [set $b]

$b is a, so [set $b] becomes [set a], and set with one argument returns the value of that variable. This is how you read a variable whose name is stored in another variable.

6. What is upvar for? Write a proc that adds 1 to a variable given by name.

upvar links a local name to a variable in the caller's scope, so a proc can change it. You pass the variable's name, not its value. It is the way to pass arrays to procs.

7. Given a list of boxes {llx lly urx ury}, return the one with the largest area.
8. Why is expr {$a + $b} better than expr $a + $b?

Without braces Tcl substitutes first and expr then parses the resulting text a second time. That is slower (the expression cannot be compiled once), and if a variable holds text like [exit] it would be executed. With braces, expr reads the variables itself.

9. How do you run an external program and not let its failure stop your script?

exec raises an error when the program exits non-zero or writes to its error stream. Wrap it in catch, which returns 1 on error and stores the message.

10. From a line like RULECHECK M1.S.1 .... TOTAL Result Count = 12 (12), extract the rule and the count.

Say why each part is there: ^ so indented by-cell lines do not match, \S+ because rule names contain dots, .*= to jump over the dots to the equals sign.

Perl

11. Difference between my $n = @list; and my ($n) = @list;

Context. The first is scalar context: you get the number of elements. The second is list context: you get the first element.

12. Count word occurrences in a file and print the top five.
13. Sort a hash by value, largest first.

Know why <=> and not cmp: cmp compares as text and would put 4 above 15.

14. Remove duplicate lines from a file, keeping the first of each. As a one-liner.

The command itself is perl -ne 'print unless $seen{$_}++' file1 file2. $seen{$_}++ is 0 (false) the first time a line appears and true afterwards.

15. What is a reference? Build a hash whose values are arrays.

A reference is a scalar that points to an array, hash or sub. Since hash values must be scalars, nested data is built from references.

16. chomp versus chop? == versus eq? die versus warn?
  • chomp removes a trailing newline only if there is one. chop removes the last character whatever it is.
  • == compares numbers, eq compares text. Using == on names makes all names equal (they are all 0 as numbers).
  • die prints to the error stream and stops with a non-zero exit code. warn prints and continues.
17. Print lines 5 to 8 of a file. Print every line that has exactly 3 fields.

Commands: perl -ne 'print if 5 .. 8' file (the range operator compares against the line number) and perl -lane 'print if @F == 3' file (-a splits each line into @F; in a comparison an array gives its length). The comment line of the list has six words, so it is not printed.

18. Swap two columns in a file. Replace a net name in a netlist only as a whole word.

Commands: perl -lane 'print "$F[2] $F[0]"' file and perl -pe 's/\bVSS\b/VSSA/g' file. \b is a word boundary, so VSS changes but VSSX would not.

19. Your regular expression /(.*)\.(.*)/ on M1.S.1 gives the wrong layer. Why?

.* is greedy: the first group takes as much as possible, so it becomes M1.S.

Scenario questions

20. The run finished with 5,000 DRC violations. What do you do first?
  1. Check the run is valid: right layout version, right top cell, right deck and switches, log finished without errors.
  2. Count per rule, sorted. Usually three or four rules hold 90% of the errors.
  3. Look for export causes first: a whole layer failing, or errors in every instance of one cell, points to the layer map, a missing cell GDS or a wrong library version, not to routing.
  4. Use hierarchy: the by-cell view shows whether 3,000 errors are one error inside a cell placed 3,000 times.
  5. Cluster by location: errors in one window usually share one cause.
  6. Compare with the previous run to see what is new.
  7. Only then open the viewer on one example of each group, and route each group to its owner.

Naming a script for each step (summary, compare, hotspot) is what turns this into a strong answer.

21. How would you automate nightly sign-off for 40 blocks?

Describe the chain: one block list as the single source of names and paths; a pre-run gate (fresh layout, top cell present, layer map and ports sane); generated run directories and control files from a template; launch through the farm with a job limit; log scan for finished, failed or still running; summaries after waivers; comparison with the previous night; one published table. Mention dry-run mode, exit codes, and that an unfinished run must never be shown as clean. Details on the Calibre page.

22. LVS is incorrect at top level. What is your order of attack?
  1. Read the verdict block and the error types.
  2. Fix the lowest incorrect cell in the hierarchy first.
  3. Check ports and text: missing or misplaced labels and wrong pin lists cause a large share of top-level failures.
  4. Check object counts: more nets in layout suggests opens, fewer suggests shorts; extra instances suggest physical cells missing from the netlist.
  5. Shorts on power and ground first; they hide everything else.
  6. Then connectivity and property discrepancies, cross-probing in the viewer.
23. When would you choose Tcl, Perl, Python or shell?
  • Tcl for anything inside an EDA tool or its rule files.
  • Perl for text reports and logs, and because the existing flow is full of it.
  • Python for new, larger utilities with structure, tests and libraries (CSV, JSON, plotting, web dashboards), if the company allows it on the farm.
  • Shell for gluing a few commands together and for job submission wrappers.

The mature answer adds: "and I follow what my team already uses, because a script nobody else can maintain is a liability."

24. Tell me about a script you wrote.

Prepare this before any interview. Four sentences: the manual task and how long it took; what your script does and in which language; the result in numbers (hours saved, errors caught before a run, how many people use it); one thing that went wrong and how you fixed it. If you have not written one yet, build one project from the project list for your team first. A small real tool beats a large imaginary one.

A drill for the last week

  • Write questions 3, 4, 7, 12, 13 and 15 on paper, no shell, ten minutes each.
  • Explain questions 1, 8, 11 and 19 aloud to someone who does not program.
  • Write one summary parser from an empty file in under fifteen minutes, in each language.
  • Rehearse your project story until it fits in two minutes.
  • Prepare two questions of your own about the team's sign-off flow and how much of it is scripted.
